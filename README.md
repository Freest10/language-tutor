# language-tutor

Локальное веб-приложение для изучения иностранного языка в голосовом диалоге с ИИ-тьютором.
Приложение определяет ваш уровень, строит план урока под ваши цели и загруженные материалы,
проводит занятие голосом или текстом, выдаёт задания и разбирает ответы. Моделей внутри нет:
языковая модель, распознавание и синтез речи подключаются по OpenAI-совместимому HTTP, поэтому
работать можно полностью локально или через облачный ключ. Профиль один, аутентификации нет —
приложение рассчитано на запуск на своей машине.

## Что умеет

- **Голосовой диалог в обе стороны.** Реплику можно надиктовать (кнопка «говорить, пока держу»)
  и услышать ответ тьютора. Распознавание и синтез делает либо браузер, либо серверный
  провайдер — переключается в `.env`.
- **План урока.** Тьютор строит план из 4–7 шагов (разминка, лексика, грамматика, чтение,
  аудирование, говорение, задания, итоги) с целями и минутами на каждый шаг. План можно
  пересобрать, не теряя историю урока.
- **Свои материалы.** Загрузите PDF с текстовым слоем, `.txt`, `.md` или вставьте текст —
  приложение разберёт его на фрагменты и будет цитировать по ходу урока.
- **Задания с проверкой.** Пять видов: перевод, подстановка пропуска, вопрос-ответ,
  множественный выбор и свободная речь. Ответ проверяет модель, а не сравнение строк,
  поэтому синонимичная формулировка или ответ голосом без пунктуации засчитываются.
- **Подстройка под уровень и цели.** Уровень CEFR определяется коротким адаптивным тестом,
  а дальше корректируется сам по результатам уроков. Цели, интересы и дневная норма из профиля
  попадают в каждый промпт.
- **Переключение языка изучения.** Английский — только значение по умолчанию; в профиле
  доступны английский, русский, немецкий, испанский и французский.
- **Прогресс.** Личный словарь со стадиями освоения, журнал ошибок по категориям и история
  изменения уровня с обоснованием.

## Требования

- **Node.js 24 или новее** и npm (проверяется полем `engines`).
- **Языковая модель** по OpenAI-совместимому адресу: локальная Ollama, LM Studio или облачный
  ключ. По умолчанию ожидается `qwen3:8b` на `http://localhost:11434/v1` — это около 5 ГиБ
  весов на диске. Модели меньше 8B заметно портят план урока и проверку ответов.
- **Браузер на Chromium** (Chrome, Edge, Arc) — чтобы голос работал без установки чего-либо
  ещё. В Firefox Web Speech API фактически нет, там нужен серверный режим голоса.
- **Docker — опционален.** Он нужен, только если вы хотите держать модели рядом с приложением
  и поднимать их одной командой; без него всё работает.

## Быстрый старт

В корне репозитория:

```bash
npm install
cp .env.example .env
```

Поднимите языковую модель (пресет по умолчанию — локальная Ollama):

```bash
ollama serve          # или нативное приложение Ollama
ollama pull qwen3:8b
```

Если Ollama не установлена, но есть Docker: `npm run stack:up` поднимет её в контейнере,
а модель скачается командой `docker compose exec ollama ollama pull qwen3:8b`.

Запустите приложение:

```bash
npm run dev
```

Поднимутся два процесса: API на `http://localhost:8787` и веб на `http://localhost:5173`
(веб проксирует `/api` на сервер). Откройте **http://localhost:5173** и пройдите путь:

1. **Профиль** — выберите изучаемый язык, язык интерфейса и язык объяснений, задайте цели
   и дневную норму минут.
2. **Определение уровня** — короткий диалог из нескольких вопросов; в конце уровень CEFR
   запишется в профиль.
3. **Материалы** — загрузите файл или вставьте текст (необязательно: урок можно построить
   и по целям профиля).
4. **Уроки** — создайте урок, при желании отметив материалы, дождитесь плана и откройте
   комнату урока. Дальше можно говорить.

Если что-то не заработало, выполните `npm run smoke` при запущенном приложении: он проходит
весь путь — сервер, модель, голосовые эндпоинты, профиль, материал, план урока — и к каждому
провалу печатает, что именно делать.

## Провайдеры голоса и модели

Все три ИИ-функции ходят по одному OpenAI-совместимому контракту, поэтому провайдер меняется
переменными в `.env` без правок кода. В `.env.example` лежат три готовых пресета:

1. **Браузерный голос + локальная LLM** (по умолчанию). Поднимать нужно только модель,
   распознаванием и синтезом занимается браузер. Цена выбора: нужен Chromium, качество голоса —
   какое даёт операционная система.
2. **Полностью локальный стек в Docker.** `npm run stack:up` поднимает Ollama (`:11434`),
   распознавание faster-whisper (`:8000`) и синтез Kokoro (`:8880`); звук не покидает машину.
   Цена выбора: несколько гигабайт образов и нагрузка на процессор.
3. **Облачный OpenAI-совместимый ключ.** Ничего поднимать не надо и качество выше, но весь
   звук и все тексты уроков уходят провайдеру, а занятия стоят денег.

Что именно настраивается, чем платишь за каждый выбор, как читать ошибки провайдера и как
проверить, что он жив, — в [docs/providers.md](docs/providers.md).

## Где лежат данные

Всё хранится в каталоге `data/` в корне репозитория, и оба пути перечислены в `.gitignore`:

- `data/app.db` — база SQLite: профиль, материалы и их фрагменты, уроки, реплики, задания,
  словарь, журнал ошибок, история уровня. Рядом появляются служебные `app.db-wal` и `app.db-shm`
  (включён режим WAL).
- `data/uploads/` — исходные загруженные файлы материалов.

Файл базы создаётся при первом запуске сервера, миграция применяется автоматически.
Пути меняются переменными `DB_PATH` и `UPLOAD_DIR`.

**Перенести на другую машину:** остановите сервер и скопируйте каталог `data/` целиком —
база и файлы материалов ссылаются друг на друга, по отдельности они бесполезны.

**Начать с нуля:** остановите сервер, удалите `data/app.db` (вместе с `app.db-wal`
и `app.db-shm`) и содержимое `data/uploads/`. При следующем запуске схема создастся заново,
в ней будет пустой профиль-заготовка. Отдельную базу удобно держать и для экспериментов:
`DB_PATH=./data/smoke.db npm run dev:server`.

## Смена изучаемого языка

Языки переключаются в разделе **Профиль**, и их там три — это не дублирование:

- **изучаемый язык** — на нём говорит тьютор, на нём же формулируются задания и примеры;
- **язык интерфейса** — подписи приложения; хранится в браузере, а не в профиле. Полные
  переводы есть для русского и английского;
- **язык объяснений** — на нём разбираются ошибки, пишутся переводы слов и итог урока.
  Смысл разделения в том, что на A1 объяснять правила нужно на родном языке, а на C1 полезнее
  на изучаемом, — и менять для этого изучаемый язык не приходится.

Изучаемый язык и язык объяснений фиксируются в уроке в момент его создания: правка профиля
не меняет язык уже идущего занятия, новые уроки создаются с новыми значениями.

## Типовые проблемы

**Микрофон не работает.** Сначала посмотрите на главную страницу: там написано, кто выполняет
распознавание и синтез. Если это браузер, проверьте, что вы в Chromium-браузере и дали доступ
к микрофону (в Firefox Web Speech API фактически нет — приложение это распознаёт и пишет прямо
на экране). Лечится переходом на серверный режим: поднимите распознавание
(`docker compose --profile stt up -d`) и задайте в `.env` `STT_PROVIDER=openai`,
`STT_BASE_URL=http://localhost:8000/v1`, `STT_MODEL=Systran/faster-whisper-small`.
Голоса Kokoro не покрывают немецкий и русский — для них оставьте `TTS_PROVIDER=browser`.

**Тьютор думает очень долго или отвечает 502/503.** Стриминга нет, поэтому пауза 5–20 секунд
на локальной 8B-модели — норма, а первый запрос ещё и грузит веса в память (`LLM_TIMEOUT_MS`
по умолчанию 120 000 мс именно поэтому). Если ответов нет вовсе:

- `npm run smoke` — он покажет, какое звено не отвечает, и что с ним делать;
- 503 обычно значит, что модель не поднята или `LLM_BASE_URL` указывает не туда;
- 502 чаще всего значит, что модель не смогла вернуть JSON по схеме: возьмите модель от 8B
  (`LLM_MODEL`), меньшие не справляются с планом урока и проверкой ответов;
- если тьютор перестаёт держаться плана — переполнено окно контекста. У Ollama оно по умолчанию
  4096 токенов, чего не хватает; поднимите его переменной сервера модели
  `OLLAMA_CONTEXT_LENGTH=8192` (в профиле `ollama` из `docker-compose.yml` она уже задана).

**`npm install` падает на `better-sqlite3`.** Это нативный модуль. Убедитесь, что у вас
Node.js 24 или новее (`node -v`) и та же разрядность, что у скачанных сборок; затем
`npm rebuild better-sqlite3`. Если готовой сборки под вашу платформу нет, понадобятся
инструменты компиляции: Xcode Command Line Tools на macOS, `build-essential` и `python3`
на Linux.

**Порт занят.** API берёт порт из `PORT`, веб — из `WEB_PORT`; оба задаются в `.env`.
Dev-сервер Vite запущен в режиме строгого порта и при занятом порте падает сразу, а не
переезжает на соседний. Контейнеры моделей слушают `11434`, `8000` и `8880` — только
на петлевом интерфейсе.

## Известные ограничения

- **Ответы не стримятся.** Реплика тьютора приходит целиком; на локальной 8B-модели это
  5–20 секунд паузы, закрытой индикатором «тьютор думает».
- **Аудио не сохраняется** — в базу попадает только расшифровка. Оценка произношения — лишь
  то, что модель выводит из текста.
- **OCR нет.** PDF без текстового слоя (скан) получает статус `error_no_text_layer`
  с пояснением. Формат `.docx` не поддерживается.
- **Отбор фрагментов материалов эвристический** — по ключевым словам и бюджету символов,
  без эмбеддингов. На больших PDF релевантность цитат падает.
- **Обоснования смены уровня генерируются сервером по-русски** и хранятся в базе как есть,
  поэтому при английском интерфейсе они останутся русскими. Сам интерфейс и язык изучения
  переключаются полноценно.
- **Голоса Kokoro не покрывают немецкий и русский** — для этих языков серверный синтез
  не подойдёт.
- **Аутентификации нет, приложение рассчитано на localhost.** Профиль, материалы и расшифровки
  уроков доступны любому, кто дотянется до порта, поэтому сервер по умолчанию слушает только
  петлевой интерфейс (`HOST=127.0.0.1`), а список источников CORS задан явно (`CORS_ORIGIN`).
  Значение `HOST=0.0.0.0` ставьте только осознанно и в доверенной сети.
- **Один пользователь, один профиль.** Многопользовательского режима и мобильного приложения
  нет.

## Архитектура

Монорепо из трёх воркспейсов npm: `shared` — контракты и доменные схемы на zod, `server` —
Fastify поверх SQLite (`better-sqlite3`), который собирает промпты и ходит к провайдерам,
`web` — React и Vite. Контракт один на обе стороны: одна и та же схема проверяет тело запроса
на сервере и даёт типы клиенту. Отдельной спецификации OpenAPI в проекте нет — источником
правды по API служат схемы из `shared/src/api/`.

Подробности — в [docs/architecture.md](docs/architecture.md).

# История изменений

Все заметные изменения этого проекта описаны в этом файле.

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
проект придерживается [семантического версионирования](https://semver.org/lang/ru/).

## [Не выпущено]

### Added

- **Десктопное приложение для macOS и Windows.** Тот же код, упакованный в Electron:
  окно открывает встроенный сервер на петле, поэтому интерфейс и API живут на одном
  источнике — без прокси, CORS и второго порта. База, материалы, настройки и журналы
  переехали в каталог пользователя, настройки лежат в `settings.json` и открываются из
  меню. Сборка: `npm run pack:mac` / `npm run pack:win` в воркспейсе `@lt/desktop`,
  матрица CI — `.github/workflows/desktop.yml`. Подробности — `docs/desktop.md`.
- **Встроенное распознавание речи (whisper.cpp).** Десктопная сборка распознаёт речь
  локально, без сети и ключей: `whisper-server` поднимается рядом и отвечает по тому же
  OpenAI-совместимому протоколу, что и облако, — второго пути распознавания в сервере не
  появилось. Браузерное распознавание в Electron не работает в принципе: Chromium
  отправляет звук в сервис Google по ключам, которых в сборках Electron нет.
- **Раздача собранного интерфейса сервером (`WEB_DIST_DIR`).** Задан каталог `web/dist` —
  сервер отдаёт интерфейс сам, включая адреса маршрутизатора браузера; ошибки API при этом
  остаются JSON-конвертом `{ error }`, а не страницей.
- **Перекодирование записи в WAV 16 кГц (`STT_REQUIRE_WAV16`).** Распознавателю, который не
  умеет распаковывать сжатый звук, браузер отдаёт запись готовым WAV. Клиент узнаёт об этом
  из `GET /api/config` (`stt.requiresWav16`); для облака флаг выключен — Opus компактнее.
- **`OCR_SCRIPTS_DIR`** — каталог помощника распознавания `macos-ocr.swift` для случаев,
  когда код лежит не рядом с ним (в установленном приложении он обязан быть обычным файлом,
  а не файлом внутри архива).

### Fixed

- **Слова на языке объяснений не озвучиваются.** Модель вставляет в реплику перевод или
  пояснение по-русски («Brush your teeth (чистить зубы)»), а голос подобран под изучаемый
  язык: серверный Kokoro русского не знает, браузерный английский голос читает кириллицу по
  буквам. Теперь перед озвучкой такие слова убираются (`features/voice/spokenText.ts`),
  а у реплики целиком на языке объяснений кнопки «переслушать» нет и автоозвучка молчит.
  Языки различаются по письменности, поэтому для пары одной письменности (немецкий с
  английскими объяснениями) ничего не вырезается.
- **Служебные пометки распознавателя не попадают в реплику.** На тишине whisper возвращает
  не пустую строку, а `[BLANK_AUDIO]` (бывают `[MUSIC]`, `(silence)`), и это приезжало в поле
  ввода как слова ученика. Сервер такие пометки убирает (`lib/transcript.ts`); слова в
  скобках, сказанные учеником, остаются на месте.
- **Тьютор больше не ходит по кругу.** Реплика, повторяющая уже сказанное, ловится сервером
  (сравнение по общим словам, `lib/repetition.ts`), и модель переспрашивается один раз с
  прямым указанием, что вопрос уже задан. Отдельная причина повторов — переполненное окно
  контекста у локальной модели — описана в README и `docs/desktop.md`: приложение задать его
  за Ollama не может, но теперь хотя бы понятно, где смотреть.

### Changed

- **Говорить можно, не удерживая кнопку.** Запись включается нажатием и выключается вторым
  нажатием — и кнопкой, и пробелом. Держать кнопку всю фразу было неудобно, а отпустить её
  посреди — обидно. Прежний режим удержания остался в компоненте и включается свойством.
- **Урок выглядит как переписка.** Реплики тьютора и ученика разведены по сторонам, у каждой
  стороны свой кружок роли, под репликой — время и способ ввода, исправления прицеплены к
  реплике заметкой на полях. Лента прокручивается внутри себя, а поле ввода живёт в той же
  панели: микрофон и отправка стоят прямо в рамке поля, ниже — запись голосом и озвучивание
  ответов. Раньше диалог был списком карточек во всю ширину, а форма ответа — отдельным
  блоком рядом.
- **Исчерпанный шаг урока закрывается сам.** Тьютор сообщает об этом полем `stepComplete`,
  сервер закрывает шаг и открывает следующий — не раньше второй реплики ученика на шаге и
  никогда при невыполненном задании. Раньше шаг закрывался только руками, и модели, которой
  нечего было спросить, оставалось повторяться.
- **Шаг закрывает сервер, если модель этого не делает.** Локальная модель флаг
  `stepComplete` почти не ставит и спрашивала «а что ещё?» у ученика, который уже сказал, что
  добавить ему нечего. Теперь у шага есть бюджет реплик ученика по его длительности в плане
  (`lib/stepBudget.ts`: по реплике на две минуты, от трёх до восьми). Когда бюджет исчерпан
  или тьютор с третьей реплики повторил уже заданный вопрос, модели прямо велят попрощаться с
  темой и открыть следующий шаг, а шаг закрывается независимо от её флага. Детектор повторов
  теперь сравнивает и финальный вопрос реплики отдельно: «Ты любишь кафе. А что ещё вы делаете
  вместе?» после «Ты любишь гулять. А что ещё вы делаете вместе?» — повтор, хотя по множеству
  слов реплики разные.
- `npm run db:migrate` запускает `server/src/db/migrateCli.ts`: раннер миграций больше
  ничего не выполняет при импорте, иначе сборка сервера в один файл применяла бы миграции
  сама по себе.
- Сообщение о пределе страниц скана больше не отсылает к `.env`: в десктопной версии его нет.

## [0.1.0] — 2026-09-16

Первый выпуск: локальное однопользовательское веб-приложение для изучения иностранного языка
в голосовом диалоге с ИИ-тьютором.

### Added

- **Голосовой диалог в обе стороны.** Реплику можно надиктовать и услышать ответ тьютора.
  Распознавание и синтез делает либо браузер (Web Speech API, без установки чего-либо),
  либо серверный OpenAI-совместимый провайдер — режим выбирается переменными
  `STT_PROVIDER` и `TTS_PROVIDER`. Расшифровка попадает в поле ввода и правится учеником
  до отправки, пометка «надиктовано» при этом сохраняется.
- **Определение уровня.** Короткий адаптивный диалог: сложность следующего вопроса считает
  сервер, итог записывает уровень CEFR и уверенность в профиль и открывает первую запись
  истории уровня.
- **Профиль ученика.** Уровень, цели, интересы, дневная норма минут и три отдельных языка —
  изучаемый, интерфейса и объяснений.
- **Учебные материалы.** Загрузка PDF с текстовым слоем, `.txt`, `.md` или вставленного
  текста, разбор на фрагменты, список с фильтрами, просмотр и удаление. Извлечение текста
  синхронное: ответ на загрузку уже содержит финальный статус, а неудача объясняется
  машиночитаемым статусом и текстом для пользователя.
- **План урока.** Генерация плана из 4–7 шагов (разминка, лексика, грамматика, чтение,
  аудирование, говорение, задания, итоги) с целями, минутами и цитатами из выбранных
  материалов; пересборка плана без потери истории урока.
- **Проведение урока.** Комната урока: реплики голосом или текстом, исправления от тьютора,
  переходы по шагам плана, завершение со сводкой. Реплика ученика сохраняется до обращения
  к модели, остальное пишется одной транзакцией после ответа.
- **Задания с проверкой.** Пять видов — перевод, подстановка пропуска, вопрос-ответ,
  множественный выбор и свободная речь; вид задания подбирается под вид шага. Ответ
  проверяет модель, поэтому синонимичная формулировка и речь без пунктуации засчитываются.
- **Прогресс.** Личный словарь со стадиями освоения, журнал ошибок по пяти категориям,
  сводка занятий и история уровня с обоснованием и метриками.
- **Автокоррекция уровня.** Уровень пересчитывается по результатам уроков с защитой от
  дёрганья: минимум завершённых уроков, окно, пороги повышения и понижения, пауза между
  изменениями и не больше одной ступени CEFR за раз.
- **Переключение изучаемого языка.** Английский, русский, немецкий, испанский и французский;
  английский — лишь значение по умолчанию. Интерфейс переведён на русский и английский.
- **Подключение моделей через `.env`.** Языковая модель, распознавание и синтез речи ходят
  по одному OpenAI-совместимому контракту; в `.env.example` три готовых пресета — браузерный
  голос с локальной Ollama, полностью локальный стек в Docker и облачный провайдер.
- **Локальные модели одной командой.** `docker-compose.yml` с независимыми профилями
  `ollama`, `stt` и `tts` плюс `npm run stack:up` / `npm run stack:down`.
- **Дымовая проверка живого стека** `npm run smoke`: здоровье сервера, конфигурация, ответ
  модели, голосовые эндпоинты, профиль, материал, план урока и прогресс — с подсказкой
  «что делать» у каждого провала.
- **Документация:** README, матрица провайдеров `docs/providers.md` и карта кода
  `docs/architecture.md`.

### Fixed

- **Ответ модели не по схеме больше не срывает создание урока.** Форму ответа держит сам
  сервер модели: приложение просит `response_format: json_schema`, и llama.cpp, Ollama,
  vLLM и OpenAI генерируют строго по схеме. Сервер, который такого режима не знает,
  молча получает `json_object`, а потом и обычный запрос — откат настраивать не нужно.
- **Урок по загруженному материалу строится на нём, а не на целях профиля.** В промпте
  стояло «тему выбери по целям и интересам», и по учебнику system design получался урок
  про приветствие: цитаты в промпте были, а план — не о них. Теперь при выбранных
  материалах тема выводится из цитат, а после них стоит отдельное напоминание, что
  и тема, и отрабатываемые слова, и примеры берутся оттуда же, причём на изучаемом языке,
  а не в переводе. Цели профиля остаются тем, _как_ работать с материалом.
- **Отказы языковой модели перестали сводиться к «повторите попытку».** Модель, которой нет
  у провайдера (Ollama отвечает на неё 404), называется по имени вместе с переменными
  `LLM_MODEL` и `LLM_BASE_URL`, а ответ, оборванный окном контекста, объясняется отдельно
  и без совета повторить — повтор оборвался бы там же. Раньше оба случая выглядели как
  «модель ответила не по схеме», и пользователь повторял запрос, который не мог пройти.

### Security

- Сервер по умолчанию слушает только петлевой интерфейс (`HOST=127.0.0.1`). Аутентификации
  в приложении нет по замыслу, поэтому сетевая привязка — единственная граница доступа
  к профилю, материалам и расшифровкам уроков.
- Список источников CORS задаётся явно (`CORS_ORIGIN`); пустое значение означает «только
  собственный веб на `localhost:WEB_PORT`», а не отражение любого `Origin`.
- Порты контейнеров моделей публикуются только на петлевом интерфейсе: `127.0.0.1:11434`
  (LLM), `127.0.0.1:8000` (распознавание), `127.0.0.1:8880` (синтез).
- Недоверенный текст — цитаты материалов и реплики ученика — уходит в промпты в именованных
  ограничителях и помечен как данные, а не инструкции модели.
- Размеры загрузок ограничены: файл материала, число и размер частей multipart и тело
  JSON-запроса (`MAX_UPLOAD_MB`).
- Сообщение об ошибке конфигурации не печатает значения ключей и вырезает учётные данные
  и строку запроса из адресов провайдеров.

### Known limitations

- Ответы модели не стримятся: на локальной 8B-модели пауза между репликами 5–20 секунд.
- Аудио не сохраняется — в базу попадает только расшифровка, поэтому оценка произношения
  ограничена тем, что модель выводит из текста.
- OCR нет: PDF без текстового слоя принимается со статусом `error_no_text_layer`. Формат
  `.docx` не поддерживается.
- Фрагменты материалов отбираются эвристикой по ключевым словам и бюджету символов, без
  эмбеддингов: на больших PDF релевантность цитат падает.
- Обоснования смены уровня генерируются сервером по-русски и хранятся как есть, поэтому при
  английском интерфейсе останутся русскими.
- Голоса Kokoro не покрывают немецкий и русский — для этих языков серверный синтез не подойдёт.
- Голос «из коробки» требует браузера на Chromium: в Firefox Web Speech API фактически нет,
  там нужен серверный режим распознавания.
- Один пользователь и один профиль; многопользовательского режима и удаления уроков нет.

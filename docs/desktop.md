# Десктопная сборка: приложение для macOS и Windows

То же самое приложение, упакованное в Electron: окно с иконкой вместо вкладки браузера,
свой сервер внутри и встроенное распознавание речи. Веб-версия никуда не девается —
десктоп это оболочка над тем же кодом, а не вторая реализация.

```
Electron (главный процесс = Node)
├── whisper.cpp            отдельный процесс, 127.0.0.1:<свободный порт>
├── сервер приложения      Fastify в этом же процессе, 127.0.0.1:<свободный порт>
│   └── раздаёт web/dist   интерфейс и API на одном источнике
└── окно                   открывает http://127.0.0.1:<порт сервера>
```

Окно открывает `http://127.0.0.1`, а не файл со сборкой: так интерфейс и API живут на одном
источнике — не нужны ни прокси, ни CORS, а микрофон работает, потому что петлю браузер
считает надёжным источником (в отличие от `file://`).

## Чем десктопная версия отличается от веб-версии

|                    | Веб-версия                          | Десктопная                                                        |
| ------------------ | ----------------------------------- | ----------------------------------------------------------------- |
| Распознавание речи | браузер (Web Speech API) или сервер | **встроенный whisper.cpp**, без сети и ключей                     |
| Синтез речи        | браузер или сервер                  | браузер (системный голос) или сервер                              |
| Настройки          | `.env` рядом с исходниками          | `settings.json` в каталоге пользователя, меню «Файл → Настройки…» |
| База и материалы   | `data/` в репозитории               | каталог пользователя (переживает переустановку)                   |
| Языковая модель    | своя, по адресу из `.env`           | своя, по адресу из настроек                                       |

**Почему распознаёт не браузер.** `webkitSpeechRecognition` в Chromium отправляет звук в
сервис Google по ключам, которых в сборках Electron нет: в окне приложения браузерное
распознавание просто не работает. Поэтому в установщик едет whisper.cpp — он работает
локально, без сети и без ключей. Синтез речи (`speechSynthesis`) системный и работает.

**Почему запись перекодируется.** Браузер пишет Opus в webm, а whisper.cpp распаковывает
звук библиотекой miniaudio, знающей WAV, MP3 и FLAC. Поэтому сервер просит клиента прислать
WAV 16 кГц моно (`stt.requiresWav16` в `GET /api/config`), и интерфейс перекодирует запись
средствами самого браузера — он этот Opus и записал. Для облачного распознавателя флаг
выключен: Opus примерно в десять раз компактнее, и распаковать его облако умеет само.

## Сборка

Нужны `git`, `cmake` (macOS: `brew install cmake`) и Node 24.

```bash
npm install
npm run whisper -w @lt/desktop   # собрать whisper.cpp и скачать модель (~150 МБ, один раз)
npm run start -w @lt/desktop     # запустить из исходников
npm run pack:mac -w @lt/desktop  # .dmg в desktop/release
npm run pack:win -w @lt/desktop  # .exe (NSIS) в desktop/release
```

Установщик под macOS собирается только на macOS, под Windows — только на Windows: этого
требуют и упаковщики платформ, и нативная сборка whisper.cpp. Поэтому обе платформы собирает
GitHub Actions — `.github/workflows/desktop.yml`:

1. **Actions → desktop → Run workflow**, выбрать ветку и платформу (обе, macOS или Windows);
2. дождаться прогона: ~10 минут, первый раз дольше — компилируется whisper.cpp, дальше он
   берётся из кэша;
3. установщики — внизу страницы прогона, в разделе **Artifacts**: `language-tutor-macOS`
   (`.dmg`) и `language-tutor-Windows` (`.exe`), zip-архивами, хранятся 90 дней.

То же из командной строки: `gh workflow run desktop.yml --ref <ветка> -f platform=обе`,
а потом `gh run download <id>`. Сборка идёт и по тегу `v*` — тогда собираются обе платформы.

`npm run pack:*` пересобирает рабочие пространства, чьи исходники новее сборки, поэтому
отдельно звать `npm run build` не нужно.

### Что попадает в установщик

|                               |                                                                         |
| ----------------------------- | ----------------------------------------------------------------------- |
| `build/app/main.js`           | оболочка Electron                                                       |
| `build/app/server.mjs`        | сервер приложения одним файлом (esbuild)                                |
| `build/app/web/`              | собранный интерфейс                                                     |
| `build/app/migrations/`       | SQL-миграции: `tsc` их не переносит, а раннер ищет рядом с собой        |
| `node_modules/better-sqlite3` | нативный модуль, в JavaScript не собирается                             |
| `node_modules/pdf-parse`      | внутри pdf.js: при сборке в один файл он теряет полифилы браузерных API |
| `resources/whisper/`          | распознаватель и модель — рядом с приложением, не в архиве              |
| `resources/scripts/`          | `macos-ocr.swift`: компилятору нужен обычный файл, а не файл в архиве   |
| `build-assets/icon.png`       | иконка приложения; установщик сам переводит её в `.icns` и `.ico`       |

Нативный модуль **не пересобирается** под Electron (`npmRebuild: false`): `better-sqlite3`
собран на N-API, а он совместим по ABI и с Node, и с Electron. Для сборки не нужен ни
компилятор, ни заголовки Electron.

Размер: ~150 МБ Electron + ~150 МБ модель распознавания + ~80 МБ pdf.js с зависимостями.

Иконка нарисована кодом — `node scripts/icon.mjs` пересобирает `build-assets/icon.png`
(1024×1024), а установщик переводит её в форматы платформ. Так её можно поправить без
графического редактора, и в истории видно, что именно изменилось. При запуске из исходников
иконку ставит сам главный процесс: иначе в доке висел бы логотип Electron.

## Настройки

Файл `settings.json` создаётся при первом запуске; меню «Файл → Настройки…» открывает его
системным редактором, «Файл → Применить настройки» перезапускает приложение.

| Платформа | Каталог                                         |
| --------- | ----------------------------------------------- |
| macOS     | `~/Library/Application Support/language-tutor/` |
| Windows   | `%APPDATA%\language-tutor\`                     |

Рядом с ним лежат `data/app.db`, `data/uploads/`, `logs/server.log` и `logs/whisper.log`.

```json
{
  "llm": {
    "baseUrl": "http://localhost:11434/v1",
    "model": "qwen3:8b",
    "apiKey": "",
    "timeoutMs": 120000,
    "temperature": 0.3
  },
  "stt": { "mode": "local", "baseUrl": "", "model": "", "apiKey": "" },
  "tts": { "mode": "browser", "baseUrl": "", "model": "", "apiKey": "", "voice": "" },
  "whisper": { "model": "ggml-base.bin", "threads": 0, "port": 0 },
  "scan": {
    "mode": "ocr",
    "visionModel": "qwen3-vl:8b-instruct",
    "maxPages": 50,
    "dpi": 150,
    "ocrLangs": ["en-US", "ru-RU"]
  },
  "logLevel": "info"
}
```

- `stt.mode`: `local` — встроенный whisper.cpp; `openai` — внешний OpenAI-совместимый
  сервер (тогда заполните `baseUrl`, `model`, при необходимости `apiKey`); `off` —
  распознавание выключено, остаётся ввод текстом.
- `whisper.model` — имя файла в каталоге моделей или абсолютный путь. Модель побольше
  (`ggml-small.bin`, `ggml-medium.bin` с [huggingface.co/ggerganov/whisper.cpp](https://huggingface.co/ggerganov/whisper.cpp))
  положите в подкаталог `models/` рядом с настройками и укажите её имя: свой каталог
  приоритетнее того, что приехал в установщике, и переустановка его не затирает.
- `whisper.threads`, `whisper.port` — 0 означает «выбрать самому».
- `scan` — что делать с PDF без текстового слоя: `mode` (`off` | `ocr` | `vision`),
  сколько первых страниц распознавать (`maxPages`), разрешение растеризации (`dpi`) и языки
  распознавания (`ocrLangs`). Учебник на 200 страниц — это заметное время работы, поэтому
  предел по умолчанию 50 страниц.

Испорченный файл не мешает запуску: неверные поля заменяются значениями по умолчанию,
верные сохраняются, а список замен показывается при старте. Файл при этом не переписывается —
правку пользователя приложение не затирает.

Экрана настроек в интерфейсе пока нет; это ближайший очевидный шаг, когда понадобится
менять модель чаще, чем раз в установку.

## Языковая модель

В установщик она не входит — это гигабайты весов. По умолчанию приложение ждёт
[Ollama](https://ollama.com) на этом же компьютере:

```bash
ollama serve
ollama pull qwen3:8b
```

Облачный ключ или другой адрес задаются в `settings.json` (`llm.baseUrl`, `llm.apiKey`).
Матрица провайдеров — в [providers.md](providers.md).

Окно контекста у Ollama по умолчанию 4096 токенов — промпт урока в него не помещается, и
llama.cpp молча срезает начало: тьютор теряет и свои правила, и начало разговора, а потом
задаёт вопросы по второму разу. Проверить — `ollama ps` (столбец CONTEXT), поднять —
`OLLAMA_CONTEXT_LENGTH=16384` в окружении сервера модели. Приложение задать это за Ollama не
может: через OpenAI-совместимый эндпоинт параметр не передаётся.

## Сканы учебников

PDF без текстового слоя приложение распознаёт само, но растеризацию страниц делает внешняя
утилита **`pdftoppm` из poppler**, и в установщик она не входит:

- macOS: `brew install poppler`; локальное распознавание — macOS Vision, ему нужен `swiftc`
  из Xcode Command Line Tools (`xcode-select --install`);
- Windows: poppler из сборок [poppler-windows](https://github.com/oschwartz10612/poppler-windows),
  распознавание — `tesseract` из PATH.

Приложение ищет утилиты в обычных местах установки (`/opt/homebrew/bin`, `/usr/local/bin`,
`C:\Program Files\...`) вдобавок к PATH: программе, запущенной из Dock или меню «Пуск»,
достаётся короткий системный PATH без каталогов пакетных менеджеров.

Без poppler работают PDF с текстовым слоем, `.txt`, `.md` и вставленный текст; скан получит
честную ошибку с указанием, чего не хватает. Уйти от этой зависимости можно — pdf.js, который
уже едет в установщике, умеет рисовать страницы сам; это отдельная работа в `pdfRaster.ts`.

## Подпись

Сборки не подписаны, и это видно пользователю:

- **macOS**: Gatekeeper откажется открывать приложение двойным щелчком. Обход — «Открыть» в
  контекстном меню и подтверждение (один раз), либо `xattr -dr com.apple.quarantine
/Applications/language-tutor.app`. Чтобы убрать предупреждение совсем, нужен Developer ID
  (99 $/год): сертификат в связке ключей, `CSC_LINK`/`CSC_KEY_PASSWORD` в окружении сборки и
  нотаризация (`notarize: true` плюс `APPLE_ID`, `APPLE_APP_SPECIFIC_PASSWORD`, `APPLE_TEAM_ID`).
- **Windows**: SmartScreen покажет «Неизвестный издатель» и потребует «Подробнее → Выполнить
  в любом случае». Убирается сертификатом издателя (OV или EV) в `CSC_LINK`.

Разрешение на микрофон в macOS запрашивается при первой записи; текст запроса и
entitlements лежат в `electron-builder.yml` и `build-assets/entitlements.mac.plist`.

## Известные ограничения

- Две копии приложения одновременно не запускаются: база SQLite одна, и второй процесс
  писал бы в неё наперегонки. Повторный запуск показывает уже открытое окно.
- Обновления не автоматические: новую версию нужно скачать и установить руками.
- Данные из веб-версии в десктопную не переносятся автоматически — это разные каталоги.
  Перенос: скопировать `data/app.db` и `data/uploads/` в каталог пользователя (таблица выше).

# Контекст фичи: веб-приложение для изучения языка с голосовым диалогом

Документ для ревью. Здесь зафиксированы исходное ТЗ, план работ, принятые допущения
с обоснованиями и **осознанные решения, которые со стороны могут выглядеть ошибкой**.
Замечания, противоречащие этому документу, — не баги: помечайте их «спорное, по ТЗ так».

## 1. Исходное ТЗ (дословно)

> мне нужно создать проект с веб интерфейсом, в котором я буду изучать английский язык
> (нужна возможность переключения языка в будущем). Мне нужно, чтобы система понимала
> голос мой и могла сама отвечать голосом (можешь для этого найти готовые ллмки, для
> локального запуска или утилиты для этого). Также чтобы она строила план мне на урок,
> я его могу загрузить материалы в проекте для изучения, мы их будем с ней проходить,
> она мне будет давать задания. Будет подстраиваться под мой уровень языка и под мои цели

## 3. Принятые допущения (ТЗ их не задаёт)

**A1. Стек — Node/TypeScript, а не Python.** В системе Python 3.14 — слишком свежий для
ML-колёс. Рантайм приложения на Node 24, ML-модели вынесены во внешние сервисы по HTTP.

**A2. «Готовые ллмки» = внешние OpenAI-совместимые сервисы.** Веса моделей в проект не
встраиваются. Все три ИИ-функции ходят по одному контракту: `/v1/chat/completions`,
`/v1/audio/transcriptions`, `/v1/audio/speech`. Провайдер меняется через `.env` без правок кода.

**A3. Дефолт голоса — браузерный.** `STT_PROVIDER`/`TTS_PROVIDER` по умолчанию `browser`
(Web Speech API). Иначе проект не запустится, пока пользователь не поднимет Docker.

**A4. Язык изучения — параметр, английский лишь значение по умолчанию.** Нигде в логике
и промптах не хардкодится «English».

**A5. Хранилище — файл SQLite** (`better-sqlite3`), без внешней БД.

**A6. Аутентификации нет — один локальный профиль.** ТЗ описывает персональное приложение.

**A7. Форматы материалов — txt, md, pdf и вставленный текст.** docx **исключён**: требует
ещё одну зависимость и в ТЗ не назван.

**A8. Уровень определяется placement-тестом и корректируется по ходу занятий.**

**A9. Ответы LLM без стриминга.** SSE и потоковый TTS удваивают сложность голосового
цикла ради латентности, которой в ТЗ нет. Следствие: на локальной 8B-модели пауза 5–20 с,
в UI это закрыто индикатором «тьютор думает» и блокировкой повторной отправки.

**A10. Аудио не сохраняется — только расшифровка.** Колонка `lesson_messages.audio_path`
зарезервирована и всегда `NULL`. Оценка произношения — только то, что LLM выводит из текста.

**A11. Подбор фрагментов материалов — эвристика по ключевым словам + бюджет символов,
без эмбеддингов.** Векторный поиск тянет ещё одну модель. Ограничение честное: на больших
PDF релевантность падает, это отражено в JSDoc.

**A12. В профиле три отдельных языка:** `learningLanguage` (что учим), `interfaceLanguage`
(язык UI), `explanationLanguage` (на каком объяснять правила). На A1 объяснять надо на
родном, на C1 — на изучаемом. Поле стоило одну строку в wp2 и миграцию + правку DTO во
всех пакетах, если добавлять позже.

**A13. Автокоррекция уровня с защитой от дёрганья.** Пороги в `LEVEL_CHANGE_POLICY`
(единственный источник правды): не раньше 3 завершённых уроков, окно 3 урока, >85% вверх /
<50% вниз, cooldown 3 урока, не больше одного шага CEFR. Без защиты уровень скакал бы
после одного неудачного задания.

**A14. «Из коробки без установки» = браузер на Chromium.** Web Speech API фактически
отсутствует в Firefox. Приложение детектит это и показывает инструкцию включить серверный
STT/TTS, а не оставляет молча неработающий микрофон.

**A15. Дефолтная модель — `qwen3:8b`.** Нужна модель 8B+ с надёжным структурированным
JSON и приличным русским. На меньшей качество плана и проверки ответов просядет.

**A16. PDF без текстового слоя (скан) — статус `error_no_text_layer`** с человекочитаемым
пояснением. OCR вне объёма.

**A17. Серверные тексты `reason` не локализуются — известное ограничение.** Обоснования
изменения уровня генерируются сервером по-русски и хранятся в БД как есть. При английском
интерфейсе пользователь увидит русский текст. Это сгенерированная проза, а не ключ
локализации. Язык интерфейса и язык изучения переключаются полноценно.

## 4. Осознанные решения, которые могут выглядеть ошибкой

**4.1. Стабы отвечали `not_configured` (501), а не `not_implemented`.** В `API_ERROR_CODES`
кода `not_implemented` нет, а конверт валидируется схемой. Маркер лежал в
`details.reason = 'not_implemented'`. К финалу заглушек не осталось.

**4.2. `POST /api/voice/tts` отдаёт JSON с `audioBase64`, а не бинарный поток.** Так ошибки
приходят тем же конвертом `{error}`, DTO тестируем, стриминга нет (A9). План предлагал поток —
контракт победил.

**4.3. Профиль сидится строкой-заготовкой с дефолтами.** `learnerProfileSchema` требует
`goals` минимум 1 и непустой `level`, а варианта «профиля нет» в контракте нет. Альтернатива
заставила бы отдавать 404 на базовом экране. Признак незавершённого онбординга — DB-колонка
`profile.onboarding_completed` и `placementCompletedAt === null`.

**4.4. Непригодный материал — это 400, а не тихий пропуск.** `createLessonResponseSchema`
равна `lessonSchema`, лишние ключи срезает сериализатор, поэтому донести `skippedMaterialIds`
в успешном ответе физически нельзя. Вместо этого 400 с перечнем `details.materials[]` —
пользователь видит, какой материал и почему не подошёл.

**4.5. `countsByCategory` в `GET /api/progress/errors` игнорируют собственный фильтр
`category`, но учитывают остальные.** Это семантика фасетного поиска: UI рисует по ним
переключатели категорий, и при учёте своего фильтра соседние счётчики обнулялись бы,
лишая пользователя возможности вернуться. Закреплено тестами.

**4.6. Сумма минут плана чинится сервером, а не отвергается.** Если модель не уложилась в
±20%, минуты масштабируются пропорционально. Выбрасывать готовый план из-за арифметики на
локальной модели — плохой размен.

**4.7. Пересборка плана обновляет шаги по `id` через UPSERT, а не DELETE+INSERT.** Иначе
`step_id` у уже сказанных реплик и сделанных попыток повисли бы, и история урока разъехалась
бы с планом.

**4.8. Реплика ученика сохраняется ДО обращения к модели.** Только в `turns`. Остальные
эндпоинты пишут одной транзакцией после успешного ответа. На локальной модели отказы
регулярны, и терять сказанное учеником недопустимо.

**4.9. Повторный `start` идущего урока идемпотентен** (200, без второго приветствия и без
обращения к модели), а не 409: комнату открывают заново после таймаута.

**4.10. `recordVocabulary`/`recordErrors` молча отбрасывают невалидные элементы.** Вход
приходит от LLM, и 400 посреди урока хуже потери одного слова. Расхождение «передали N,
сохранилось M» пишется в `logger.debug`.

**4.11. Язык объяснений в уроке берётся из `lesson.explanationLanguage`, а не из текущего
профиля.** Иначе правка профиля меняла бы язык разборов посреди занятия.

**4.12. Остаются 4 warning `react-refresh/only-export-components`** (0 errors) в
`CapabilitiesProvider.tsx` и `router.tsx`. Чинятся только переносом хука и констант в
отдельные файлы, что сломало бы контракт, на который сели 8 параллельных пакетов. Влияют
исключительно на гранулярность hot-reload. **Не исправлять.**

**4.13. Индикатор громкости считается только в серверном режиме STT.** В браузерном режиме
микрофоном владеет Web Speech; второй `getUserMedia` ради индикатора не запрашивается.

**4.14. Подтверждение удаления — собственный компонент, а не `window.confirm`.** Нативные
модалки блокируют поток и плохо тестируются.

**4.15. `GET /api/config` сообщает конфигурацию, а не живую доступность.** Провайдеры не
пингуются — это дороже всего остального ответа. Живую проверку делает `npm run smoke`.

**4.16. `DELETE /api/lessons/:id` намеренно не реализован** — эндпоинта нет в контракте
`@lt/shared`, в ТЗ удаление уроков не заявлено.
